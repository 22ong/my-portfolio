# 포트폴리오 웹사이트 요구사항

> 상태: **v1.1** (2026-10-08) — 요구사항 확정 + 디자인 방향 구체화(D22~D35, 5절). 디자인·개발 단계 세부 사항은 10절 참고
> 표기: ✅ 확정 · 🟡 제안(검토 필요) · ❓ 미결

---

## 1. 개요

### 1.1 목적
UI 디자이너로서 **리디자인·웹 디자인 역량**을 채용 담당자에게 설득력 있게 보여주는 개인 포트폴리오 사이트.

### 1.2 타깃 사용자 ✅
| 대상 | 상황 | 원하는 것 |
|---|---|---|
| 채용 담당자 (1차) | 지원서 링크를 통해 짧게 훑어봄 (1~3분) | 대표작 몇 개, 직무 적합성, 연락처·이력서 |
| 디자인 리드/면접관 (2차) | 면접 전에 자세히 검토 | 문제 정의 → 근거 → 결과로 이어지는 **사고 과정** |

### 1.3 성공 기준 🟡
- 첫 화면에서 5초 안에 "누구이고 무엇을 하는 사람인지" 알 수 있다.
- 메인에서 클릭 1번이면 프로젝트 시안을 볼 수 있다.
- 모든 페이지에서 이력서와 연락처에 한 번에 접근할 수 있다.
- 시안 이미지가 데스크톱·모바일 모두에서 **읽을 수 있는 크기**로 보인다.
- 사이트 자체가 디자인 역량의 증거가 된다 (정렬, 타이포그래피, 여백, 디테일).

## 3. 사이트 구조

```
/                       메인 (원페이지 스크롤)
├─ #hero                소개 한 줄 + 대표 비주얼
├─ #projects            프로젝트 카드 목록
├─ #about               소개 · 역량 · 툴
└─ #contact             연락처 · 이력서

/projects/:slug         프로젝트 상세 (시안 이미지 뷰어)
*                       404
```

공통: 상단 고정 내비게이션(섹션 앵커 + 이력서 버튼, 5.5), 푸터(연락처·SNS).

## 4. 페이지별 요구사항

### 4.1 메인 — Hero
- 이름, 직무 + 접근법을 담은 **한 줄 소개** ✅(방향) / ❓(문구). 예시: "사용자의 불편을 구조로 푸는 UI 디자이너"
  - 문구 제약: Display 크기(72–96px)로 **데스크톱 2줄 이내**, 모바일 3줄 이내.
- CTA: `프로젝트 보기`(스크롤) / `이력서`(PDF, 등록 시에만)
- 비주얼 ✅ (D24): **텍스트 중심**. 대표작 이미지는 쓰지 않는다.
  - 대신 첫 화면(1440×900 기준) 하단에 **프로젝트 카드의 윗부분이 잘려 보이도록** 배치해 스크롤을 유도하고 클릭 1번 접근을 만족시킨다.
  - 모바일에서도 첫 화면 하단에 카드 윗부분이 보여야 한다.

### 4.2 메인 — Projects
- 프로젝트 카드: 썸네일, 제목, 한 줄 요약, 성격 태그(`개인 리디자인` / `프로젝트`) (D15)
  - 개인 리디자인은 "의뢰받지 않은 개선안"임이 태그만으로 드러나므로 신뢰에 유리하다.
  - 프로젝트 작업이 팀 작업이라면 카드에 역할(예: "UI 디자인 담당")을 함께 표시한다.
- **레이아웃: 동일한 크기의 카드 그리드** ✅ (D26)
  - 데스크톱 **3열**, 썸네일 **4:3** / 태블릿 2열 🟡 / 모바일 1열
  - 3개일 때 한 줄에 딱 맞고, 늘어나도 같은 규칙으로 줄바꿈된다.
- 호버·포커스 동작은 5.6, 카드 시각 스펙은 5절 참고
- 표시 순서는 데이터의 `order` 값으로 조정
- 카드를 클릭하면 `/projects/:slug`로 이동

### 4.3 메인 — About
- 짧은 자기소개 (3~4문장) ✅
- 디자인 프로세스·강점 키워드 ✅
- 사용 툴: Figma 등 ❓ 목록 (텍스트 나열, 아이콘 없이)
- 경력·학력 타임라인과 프로필 사진은 **넣지 않는다** (D31). 경력은 이력서 PDF로 대신한다.
- 한 화면 안에서 끝나는 분량을 유지한다.

### 4.4 메인 — Contact
- 이메일 (복사 버튼 + mailto) — **유일한 필수 항목**
- 이력서 PDF 다운로드, 외부 링크(Behance / LinkedIn / 노션 등)
  - 아직 준비된 것이 없으므로(D17) `src/content/profile.ts` 설정 파일에 값을 채우면 나타나고, 비워 두면 숨겨진다.
  - 내비게이션의 `이력서` 버튼도 PDF가 등록돼 있을 때만 표시한다.
  - ⚠️ 채용 맥락에서 이력서는 사실상 필수 → 공개 전까지 준비 권장 (9절)
- 문의 폼은 넣지 않음 (채용 맥락에서는 이메일로 충분하고, 백엔드가 필요 없음)

### 4.5 프로젝트 상세 — 시안 이미지 뷰어 ✅(방향) / 🟡(세부)

구성:
1. **헤더 (HTML 텍스트)** — 제목, 한 줄 요약, 메타 정보(성격 태그 / 역할 / 기간 / 툴 / 팀 구성)
   - 이미지만 보여주면 훑어보는 채용 담당자가 맥락을 놓친다. 핵심 정보는 텍스트로 둔다.
   - (선택) Figma 프로토타입·라이브 사이트 링크
2. **시안 이미지** — 프로젝트당 긴 이미지 한 장(D11)을 세로로 보여줌
3. **이전 / 다음 프로젝트** 내비게이션 + 목록으로 돌아가기

시안 이미지 처리 🟡:
- **업로드는 한 장, 화면에는 자동으로 잘라서 표시**
  - 사용자는 긴 이미지 한 장만 폴더에 넣는다.
  - 빌드할 때 스크립트가 이미지를 일정 높이(예: 2000px) 조각으로 자르고 WebP/AVIF로 변환한다.
  - 조각을 빈틈 없이 이어 붙이므로 화면에서는 한 장처럼 보인다.
  - 이유: 초장문 이미지를 통째로 쓰면 첫 화면이 늦게 뜨고, 모바일 메모리 부담이 크다. 일부 모바일 브라우저에서는 축소 디코딩돼 흐려질 위험도 있다(실제 시안으로 검증 필요). 조각으로 나누면 화면에 들어온 부분만 로드된다.
- **크기가 제각각인 시안 처리** (D14)
  - 파이프라인이 원본의 너비·높이를 읽어서 처리한다. 사용자가 크기를 맞출 필요는 없다.
  - 너비가 표시 폭의 2배(레티나용)보다 크면 그 폭으로 줄이고, 작으면 확대하지 않고 그대로 쓴다.
  - 자르는 높이는 고정값(예: 2000px)으로 두고, 마지막 조각은 남은 만큼만 자른다.
  - 화면에서는 시안을 콘텐츠 폭에 맞춰 보여준다. 원본이 좁으면 원본 크기 이상으로 늘리지 않는다.
  - export 권장 사항(강제 아님): 1x 기준 1440~1920px 폭을 **2x로 export**하면 라이트박스 확대 시에도 선명하다.

**샘플 시안 검증** (청주시 가족센터 리디자인, 2026-10-08)
| 항목 | 값 | 시사점 |
|---|---|---|
| 크기 | 1920 × 9154px, JPG 6.17MB | 2000px 높이로 자르면 5조각. WebP 변환으로 용량 대폭 감소 예상 (구현 시 측정) |
| 구성 | 표지 → Overview → Mood board → Design System → As-is(문제점 주석) → To-be(개선점 주석) → 마무리 | 상세 헤더의 텍스트 설명은 Overview·As-is 주석 내용을 요약하면 된다 |
| 배경 | 종이 질감 + 일러스트가 이미지 가장자리까지 이어짐 | 흰 칸 안에 넣으면 어색함 → **전체 폭 표시 (D19)** |
| 주석 글씨 | 원본 기준 본문 약 20px | 화면 폭별 실제 크기: 1920 → 20px · 1440 → 15px · 1200 칸 → 12.5px · 모바일 375 → **약 4px** |
| 캡처 속 UI 글씨 | 원본 기준 약 8~10px | 데스크톱에서도 라이트박스 확대가 유용 |

- 결론: 데스크톱은 전체 폭이면 읽을 만하다. 모바일은 라이트박스가 **필수**다 (D10 재확인).
- 이 시안은 1x(1920px)라서 라이트박스 확대 한계는 원본 해상도까지다. 다음 시안부터 2x로 export하면 확대했을 때 더 선명하다 (선택).

## 5. 디자인 원칙과 스펙

### 5.1 원칙
- **작업물이 주인공**: 사이트 UI는 중립적인 색과 넉넉한 여백. 강조색은 1개만 사용. 시안 이미지의 배경색과 충돌하지 않게 한다.
- **에디토리얼 미니멀** ✅ (D22): 장식(그림자, 그라데이션, 둥근 카드 면)이 아니라 **타이포그래피·여백·1px 선**으로 구조를 만든다.
- **타이포그래피 중심**: Pretendard 단일 폰트 (D25), 크기와 굵기로 위계를 만든다.
- **그리드 일관성**: 12컬럼 그리드, 8px 간격 체계.
- **절제된 모션**: 스크롤 진입 시 가벼운 페이드 정도. `prefers-reduced-motion`을 지원한다.
- 라이트 모드만 지원 (D18).
- **Figma → 코드 연결**: Figma에서 컬러·타이포·간격을 스타일/변수로 정의하면 그대로 `src/App.css`의 `:root` CSS 변수(디자인 토큰)로 옮긴다.

### 5.2 색상 ✅ (D23)
- 기본은 **무채색**: 배경 흰색 계열, 본문 near-black, 보조 텍스트·구분선 회색 2~3단계.
- **강조색 1개**는 링크, CTA, 성격 태그, 포커스 링에만 쓴다. 넓은 면(배경)에는 쓰지 않는다.
- 강조색 후보 3~4개를 Figma에서 **프로젝트 시안 3개 옆에 나란히 놓고** 비교해 정한다. 기준은 시안 배경과 충돌하지 않는지다.
- 텍스트 위에 쓰는 강조색은 흰 배경 기준 명도 대비 4.5:1 이상 (WCAG AA, 6.3).
- 라이트박스 배경만 예외로 어두운 반투명을 쓴다 (D33).

### 5.3 타이포그래피 ✅ (D25, D34)
| 단계 | 용도 | 데스크톱 | 모바일 |
|---|---|---|---|
| Display | Hero 문구 | 72–96px, SemiBold, 줄간격 약 1.1 | `clamp()`로 36~40px |
| Heading | 섹션 제목, 프로젝트 제목 | 🟡 32–48px | 🟡 24–28px |
| Body | 본문, 소개, 설명 | 16px, Regular, 줄간격 약 1.6~1.7 | 16px |
| Caption | 섹션 라벨, 태그, 메타 | 🟡 12–14px, Medium | 12–14px |
- 굵기는 Regular / Medium / SemiBold 세 가지만 쓴다. 숫자와 영문 라벨은 같은 폰트를 쓴다.
- 한글은 단어 단위 줄바꿈(`word-break: keep-all`)을 기본으로 한다. 🟡
- Heading·Caption의 구체 수치는 Figma에서 정한다. Display와 Body는 위 값을 기준으로 한다.
- 웹폰트 용량은 Pretendard 가변 폰트의 서브셋(동적 서브셋)을 쓰는 것을 기본으로 하고, 개발 단계에서 `font-display: swap`과 함께 점검한다. 🟡

### 5.4 레이아웃과 간격 ✅ (D30, D35)
- 본문 최대 폭 **1200px**, 12컬럼 그리드. 카드 3열은 컬럼 4개씩이다. 컬럼 간격은 🟡 24px.
- 좌우 여백은 모바일 🟡 20px, 태블릿 🟡 40px, 데스크톱은 중앙 정렬.
- 메인 섹션: 상하 여백 **120~160px** (모바일은 🟡 80px), 각 섹션 위에 **섹션 라벨**(`01 Projects`, `02 About`, `03 Contact`)과 1px 구분선.
- 프로젝트 상세: 헤더(1200px 폭) → 여백 **96px** → 시안(전폭). 구분선은 넣지 않는다.

### 5.5 내비게이션 ✅ (D28, D29)
- **상단 고정**. 스크롤하면 높이가 줄고 배경에 얇은 아래 선이 생긴다. 🟡 기본 72px → 스크롤 시 56px.
- 구성: 이름(홈 링크) / Projects · About · Contact / `이력서`(PDF 등록 시에만, 4.4).
- 상세 페이지에서는 처음부터 낮은 높이로 두어 시안을 가리는 면적을 줄인다.
- **모바일**: 햄버거 메뉴 없이 텍스트 링크를 가로로 나열한다. 이름 + 링크 3개 + 이력서가 한 줄에 들어가야 한다 (이력서가 없으면 3개). 좁은 폭에서 안 들어가면 이름을 로고 마크로 줄인다. 🟡
- 키보드 포커스: 강조색 포커스 링, `Skip to content` 링크 제공.

### 5.6 컴포넌트 상호작용 ✅ (D32)
- **프로젝트 카드**: 썸네일(4:3) + 제목 + 한 줄 요약 + 성격 태그. 호버·키보드 포커스 시 썸네일 🟡 1.03배 확대(0.3s)와 제목 밑줄. 카드 전체가 하나의 링크다.
  - 모든 정보는 평소에도 보이고 호버는 보조 신호일 뿐이므로, 호버가 없는 모바일에서도 정보 손실이 없다.
  - `prefers-reduced-motion`에서는 확대를 끄고 밑줄만 남긴다.
- **링크·버튼**: 텍스트 링크는 호버 시 밑줄. CTA 버튼은 🟡 두 종류(Primary: 강조색 채움 / Secondary: 선만)로 제한한다.
- **이메일 복사 버튼**: 복사 후 버튼 문구가 "복사됨"으로 잠깐 바뀐다. 🟡
- **이전/다음 프로젝트**(상세 하단): 텍스트 + 썸네일 없이 제목만 크게. 🟡

### 5.7 라이트박스 UI ✅ (D33)
- 배경: 검정 계열 반투명(🟡 약 90%). 시안 색을 왜곡하지 않는 중립 배경이다.
- 컨트롤: 닫기(X) 버튼과 현재 배율 표시만 둔다. 이전/다음 이미지·다운로드·페이지 표시는 넣지 않는다 (조각 이미지가 한 장처럼 이어지므로).
- 컨트롤은 시안을 가리지 않는 가장자리에 두고, 모바일에서 터치 영역은 44px 이상이다.
- 동작은 4.5, 접근성은 6.3 참고.

### 5.8 모션
- 스크롤 진입 시 페이드 + 🟡 8~16px 위로 이동(0.4~0.6s) 정도. 한 번만 재생한다.
- 라이트박스 열림/닫힘은 짧은 페이드(🟡 0.2s).
- `prefers-reduced-motion: reduce`에서는 모든 이동·확대 모션을 끈다.

### 5.9 Figma 단계의 산출물 체크리스트
- [ ] 페이지 시안: 메인(데스크톱·모바일), 프로젝트 상세(데스크톱·모바일), 라이트박스, 404
- [ ] 스타일/변수: 색상(무채색 단계 + 강조색), 타이포 4단계, 간격(8px 체계), 컬럼 그리드
- [ ] 상태: 카드·링크·버튼의 기본/호버/포커스, 내비게이션의 기본/스크롤 후
- [ ] 직접 제작 썸네일 3개 (4:3, 예: 1200×900)
- [ ] 강조색 비교판: 후보를 프로젝트 시안 3개 옆에 놓은 화면

## 6. 비기능 요구사항

### 6.1 반응형
- 브레이크포인트: 모바일(~767) / 태블릿(768~1199) / 데스크톱(1200~)
- 채용 담당자는 메신저 링크로 **모바일에서 처음 열어볼 수 있다** → 4.5의 라이트박스가 필수

### 6.2 성능 (이미지가 많은 사이트)
- Figma에서 내보낸 PNG는 용량이 크다 → 빌드 시 **자동 분할 + WebP/AVIF 변환 + 반응형 `srcset` 생성** (4.5)
- 이미지 지연 로딩(lazy loading). 단, 상세 페이지의 첫 조각은 즉시 로드
- 이미지 로드 전 레이아웃 흔들림(CLS)이 없도록 `width`/`height`를 지정
- 상세 페이지는 라우트 단위 코드 스플리팅
- 목표: Lighthouse Performance 90+, LCP 2.5초 이하 (모바일 기준)

### 6.3 접근성
- 시맨틱 마크업, 키보드 탐색 가능, 포커스 표시
- 시안 이미지에 `alt` 텍스트 + 프로젝트별 텍스트 설명 — 설명이 이미지 안에만 있으면 스크린 리더와 검색엔진이 읽을 수 없다
- 라이트박스: 열리면 포커스를 안으로 옮기고, 닫히면 원래 위치로 돌려준다
- 사이트 UI 텍스트의 명도 대비는 WCAG AA 이상

### 6.4 SEO / 공유
- 페이지별 `<title>`, `description`
- **OG 이미지**: 링크를 공유했을 때 미리보기 카드가 보이도록 설정
  - v1은 사이트 공통 OG 이미지 1장. 지원서에는 메인 링크를 주로 쓰므로 이것으로 충분하다.
  - 현재 스택(SPA)은 프로젝트별 OG 태그가 기본적으로 동작하지 않는다 → 필요해지면 빌드 시 프리렌더링을 추가 (v1 이후)

### 6.5 언어 ✅
- 한국어만 (D12). `<html lang="ko">`

| 라이트박스 | 직접 구현 vs 라이브러리(예: PhotoSwipe) ❓ | 핀치 줌의 완성도를 보고 개발 단계에서 결정 |
| 배포 | Vercel ✅ (D13) | `vercel.json`에 SPA rewrite 설정 |
| 도메인 | 우선 `*.vercel.app`, 개인 도메인은 선택 ❓ | |

데이터 모델 초안:
```ts
type Project = {
  slug: string;                    // URL과 이미지 폴더 이름
  order: number;                   // 메인 노출 순서
  title: string;
  summary: string;                 // 카드·헤더용 한 줄 요약
  category: "redesign" | "project";  // 개인 리디자인 / 프로젝트 (D15)
  role: string[];
  period: string;
  tools: string[];
  team?: string;                   // 팀 작업일 때 구성·기여도 (예: "디자이너 2, 개발자 3 / UI 전담")
  description: string;             // 시안 내용 텍스트 요약 (접근성·SEO, 상세 헤더에 표시)
  designAlt: string;               // 시안 이미지 alt
  links?: { label: string; url: string }[];  // 프로토타입, 라이브 사이트 등
  // 썸네일·시안 이미지는 slug 폴더에서 자동으로 연결 (데이터에 경로를 적지 않음)
};
```

**프로젝트 추가 절차** (D5 — 코드 수정 없음):
1. Figma에서 긴 시안 한 장 + 썸네일을 export
2. `content/projects/<slug>/`에 `design.jpg`(또는 `.png`), `thumbnail.jpg`(또는 `.png`)로 넣기
   - `<slug>`는 URL이 되므로 영문 소문자·하이픈 (예: `cheongju-family-center` → `/projects/cheongju-family-center`)
3. `projects.ts`에 항목 하나 추가 → 메인 카드와 상세 페이지가 자동으로 생성됨
4. GitHub에 push → Vercel이 자동 배포

## 10. 남은 결정 사항

요구사항 토론에서 나온 질문(Q1~Q13)은 모두 결정 로그(D5~D18)로 정리했다. 남은 항목은 아래 단계에서 정한다.

### 10.1 사이트 디자인(Figma) 단계에서 정할 것
방향은 5절과 D22~D35에서 정했고, 아래는 **수치·문구 수준**으로 남은 항목이다.
- Hero 한 줄 소개 문구 (방향: 직무 + 접근법, 데스크톱 2줄 이내)
- 강조색 (후보를 프로젝트 시안 3개 옆에 놓고 비교, 5.2)
- Heading·Caption 크기, 컬럼 간격, 좌우 여백, 태블릿 열 수 (5.3, 5.4)
- 내비게이션 높이와 모바일에서 한 줄에 안 들어갈 때의 처리 (5.5)
- About 소개 문장, 강점 키워드, 툴 목록
- CTA 버튼 두 종류의 모양 (5.6)

### 10.2 개발 단계에서 정할 것
- 라이트박스: 직접 구현 vs 라이브러리 (핀치 줌 품질 비교)
- ~~이미지 분할 높이~~ → 2000px로 검증 완료 (4.5)
- 자동 썸네일을 16:10 → 4:3으로 바꾸도록 `scripts/process-images.mjs` 수정 후 용량 재측정 (D27)
- 개발 서버 실행 중에 새 시안을 넣으면 반영되도록 감시 기능을 넣을지 (현재는 서버 재시작 필요)
- 개인 도메인 연결 여부 (언제든 추가 가능)
